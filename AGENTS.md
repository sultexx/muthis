## Overview

Arabic-first voice sidekick for Windows 11. The user **holds** the **push-to-talk hotkey** (default **F9**,
configurable via `MUTHIS_HOTKEY`) while speaking Arabic and releases to send,
and Mut'his answers with Arabic speech (ElevenLabs TTS, Gemini fallback) while pointing at on-screen UI elements with a
**cyan rectangle overlay**. Reasoning + vision: **Claude Sonnet** (`claude-sonnet-4-6`) via the official
`anthropic` SDK with SSE streaming — **and, since DEC-91, a SECOND reasoner behind the same contract**
(`gpt-5.6-luna`, `openai` SDK), selected with `MUTHIS_REASONER` in `.env`. **Claude remains the DEFAULT and that
is a ruling, not an ordering.** The kernel never learns which vendor answered; there is **ONE persona for both**,
and no provider-specific persona text exists anywhere (test-enforced).

**LOOK-ONLY OVER THE USER'S MACHINE — PERMANENT, NOT A PHASE.** Mut'his speaks and points, with **zero control
over the user's session, system, and input devices** — it does **not** click, type, press hotkeys, or touch the
clipboard. Trust Modes (ASSIST / AUTOPILOT) — the only mechanism ever designed to move this boundary
(designed only in the archived, non-authoritative architecture doc — DEC-43) — are **CANCELLED from the product
vision** (DEC-6, ratifying Sultan's decision of
2026-07-14): removed by DESIGN, not deferred by timing. There is no future "Trust Modes opening" to build
toward. Do not build them, do not stub them, do not add their tools to any schema — not now and not later.
**The one constitutionally-approved execution carve-out (V2 Roadmap
decision #0; boundary sign-off 2026-07-19 — see DEC-3):** code execution is permitted **EXCLUSIVELY inside the
Mut'his-owned sandbox** (`sandbox.execute`) — `--network none` by default, no user-file access without explicit
per-run consent, instantly killable (F9). This does **NOT** relax LOOK-only for the user's machine: the mouse /
keyboard / clipboard boundary above is **untouched and absolute**, execution is confined to the container (never
the user's session), and the `type_text` / `press_hotkey` / `real_click` / `set_trust_mode` bans below stay in
force — this is the ONLY boundary that moves, and only by explicit sign-off. **`sandbox_exec` SHIPPED (Phase 2
M1, live-signed 2026-07-22, merged to `main`)**, and **`web_research` SHIPPED (Phase 2 M2, live-signed
2026-07-29)** — the model can now search the web and read a page. Reading the web moves NO action boundary (it is
perception, like `read_local_file`), but it is the first time HOSTILE text enters a turn, so it arrives with the
untrusted-content machinery: one central wrap, session-sticky taint, and a two-turn spoken confirmation for
high-impact calls (DEC-14/15/16). See `docs/reports/phase2_m2_web_research.md`.
**v7 Phase 4 added `read_local_file`** — a READ-ONLY perception tool (like `request_screen_refresh`): it reads a local TEXT file so explanations are grounded
in real content, never writes or executes anything itself, and does NOT move the action boundary.

Hardware target: Windows 11, RTX 4060 8 GB. The app must use ~0 GB VRAM and never compete with the user's
Blender/YOLO workloads. Everything heavy is cloud.

## Architecture

```
PTT hold → mic streaming capture (record while held, flush on release) →
   STT (ElevenLabs Scribe, language pinned "ar") → ClaudeAgent.run()
   → TextDelta stream → buffer-then-speak TTS (accumulate the full reply, then
     speak it ONCE at end-of-turn; ElevenLabs WS PRIMARY with progressive audio, Gemini fallback)
     — v7, flag MUTHIS_STREAM_TTS: ONE continuous ElevenLabs generation per TURN (turn_voice.py);
     the pass-1 ack is FED (instant, non-blocking) and pass-2 sentences join the SAME generation,
     hiding the inter-pass round-trip (measured 3.48 s of silence) behind the ack playback;
     v7.1: the WS handshake opens EAGERLY at turn start (begin_open, overlapping the vision pass),
     the persona makes the pass-1 spoken ack MANDATORY (a measured chars=0 ack left the gap
     unmasked), and the 7 s overlay auto-hide arms ONCE at SPEECH END (run_turn's finally),
     never at the draw;
     v7 Phase 3 (BARGE-IN, flag MUTHIS_BARGE_IN default ON): an F9 press WHILE a turn is speaking
     interrupts the teacher — UI wiped instantly (hide), the device silenced via Pa_AbortStream
     (~100 ms, measured), the turn task cancelled AFTER the voice is closed (no fallback re-speak),
     the fresh recording preserved through the old turn's reset, and the NEXT turn carries the
     INTERRUPTED_NOTE_AR internal directive
   → ToolCall(highlight_target) → gliding pointer → cyan rectangle + Arabic caption (Tk overlay)
   → TurnComplete(usage, cost) → budget.py
   → if stop_reason == "tool_use": append tool_result, loop back to run() (agentic loop,
     ≤ MAX_AGENTIC_ITERATIONS=4, budget-gated per pass) so the explanation lands AFTER the pointer
```

### Key Architecture Decisions (and the Clicky lessons behind them)

**Shared HTTP client + TLS warmup**: `ClaudeAgent` owns ONE long-lived `httpx.AsyncClient`, passed into
`AsyncAnthropic`, and fires a HEAD warmup through that same client at startup. Warming a different client is
theater — the pool must be shared (Clicky hit "Socket is not connected" by recreating sessions per request).

**Image media-type sniffing**: PNG (`89 50 4E 47`) vs JPEG (`FF D8 FF`) detected from leading bytes before
declaring `media_type`. The API rejects mismatches.

**Partial JSON discipline**: tool inputs stream as `input_json_delta` fragments. They are buffered per content
block and parsed only at `content_block_stop`. Partial JSON never leaves `claude_agent.py`.

**Structured tools, not text tags**: Clicky parses `[POINT:x,y]` tags out of prose; Mut'his uses real tool
calls (`highlight_target`). Never regress to regex-parsing coordinates from response text.

**Stateless wrapper**: `ClaudeAgent.run()` is one provider turn. No retries, no loops, no conversation memory
inside the wrapper — history AND the agentic loop (tool_use → tool_result → re-call run(), ≤4×) are the
orchestrator's (**LAW 11** — its home is CONTRIBUTING.md acceptance condition 4, which names it and extends it
to plugins: wrappers own no lifecycles, locks, or events).

- **Security guards are MUTATION-VERIFIED, and every mutation run sets `PYTHONDONTWRITEBYTECODE=1`**
  (standing rule, 2026-07-25). A guard is trusted only once the code it guards has been broken on purpose and
  the test went RED (DEC-12's principle: a check that can pass without exercising the guard is not a check).
  The interpreter flag is not hygiene — it is load-bearing. A mutation edit typically lands in the SAME second
  as the file it replaces and often at the SAME byte size, so CPython's `__pycache__` validity check
  (mtime-seconds + size) can accept the STALE `.pyc` and run the ORIGINAL code. That produces a FALSE GREEN:
  the mutation looks survived, i.e. a guard appears to hold while never having been exercised at all — the one
  failure mode that would quietly discredit every guard in the milestone. Measured live on 2026-07-25 (the T5
  classification run). Clear `__pycache__` if a result ever looks impossible, and re-run.
- **AN UNOBSERVABLE MUTATION SURVIVOR IS EXPLAINED, NEVER EXCUSED — AND "UNOBSERVABLE" IS NEVER A LICENCE TO
  DELETE THE CODE** (standing rule, 2026-07-31, earned by the `doc_rag` T6 survivor M15). Two halves, both
  binding. They COMPLETE the mutation rule above: that rule says a guard is trusted only once it has been
  broken on purpose; this one says what to do when breaking it changes nothing.
  **(1) "Unobservable" is a fact about the TEST, not a licence to delete the code.** A mutation can survive
  because the property it targets is enforced UPSTREAM, and the surviving code is then usually correct
  defensive design at a layer boundary. M15 mutated the broker's delivery sort: redundant ON THAT PATH,
  because `SessionIndex.search` already returns best-first via `argsort` — but `select` is duck-typed over a
  plain `Sequence`, and DEC-46 assigns aggregation and ordering to the PLUGIN, which may not assume a
  pre-sorted broker. **Deleting code because ONE path cannot see it withdraws the guarantee from every caller
  that path does not exercise.**
  **(2) A survivor with a KNOWN mechanism is CLOSED; a survivor with an UNKNOWN mechanism is NOT.** Closing
  requires BOTH a measurement of *why* it survived AND a control showing the property is genuinely tested
  somewhere. For M15 that control is M21: remove the INDEX's ranking (`argsort` → index order) and the
  ordering test goes RED — so the test does discriminate relevance ordering and simply cannot distinguish a
  SECOND, redundant application of it. Without both, the survivor stays OPEN. **"Probably fine" is the exact
  state a mutation run exists to destroy**, and a survivor left unexplained silently re-admits it.
- **A GUARD'S REFERENCE MUST BE OUTSIDE THE BLAST RADIUS OF THE DEFECT IT CHECKS FOR** (standing rule,
  2026-08-05, earned by the DEC-91 survivor M7). **This is a NEW FACE of "a check that can pass without
  exercising its guard", and the distinction is what makes it worth a separate rule.** Every earlier instance
  was a check that EXAMINED LESS THAN IT CLAIMED — a filter that excluded its own subject (DEC-50), a glob that
  matched nothing, a model refusing at the prompt layer so the guard never ran (DEC-12) — and every one of them

  claimed, over the real catalogue, with a correct admitted count. What was wrong was its REFERENCE: it

  earlier test in the same file had already triggered the in-place write — so the snapshot faithfully captured
  the ALREADY-POLLUTED state and **the guard compared corruption against itself and reported success.** No
  cutoff report would have caught it, because nothing was missing.

  THIRD sighting). A refusal or deferral that reports only what did NOT happen produces a **retry loop**,
  because retrying is exactly what a competent agentic model does with an unexplained failure — and the
